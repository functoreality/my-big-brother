# 存储与采集需求

[English](../REQUIREMENTS.md)

这是采集器、输入适配器和复盘任务共同遵循的产品需求。
修改日期、路径或采集器依赖之前，先阅读本文。

## 采集使用自然日期

- 时间戳始终记录真实系统时间，带时区偏移。
  Vim 例外，保留原有本地 `YYYY-MM-DD HH:MM:SS` 格式，
  读取器报告所用的本地时区假设，其他来源仍要求带偏移。
- 会话目录采用开始记录时的本机自然日期，等价于 `date +%F`：
  `daily/YYYY-MM-DD/<来源>/`。日期在创建记录时确定，不按后续写入日期重选。
  自然日或逻辑日切换都不能移动或拆分已经开始的记录。
- 跨平台 Python 用本地 `strftime("%Y-%m-%d")` 得到相同结果，
  不为格式化日期而要求 Windows 安装 Unix `date` 命令。
- 采集器不理解复盘工作日分界，不减去小时数来选择日期。
  Bash 和 Vim 都使用会话启动日期。
- Bash 每个开启记录的 shell 进程只对应一个 JSONL。
  启用采集器时一次性确定路径、初始目录和自然日期。
  即使持续数月或执行 `cd`，也始终追加到同一文件。
  命令完成时间不参与选择保存目录。
- 每张截图是独立记录，按自身拍摄日期保存。
- Vim 一个编辑器进程对应一个会话，按会话启动时的本机自然日期归档，
  跨午夜也不换目录。已有文件打开当下保存原始快照，退出时统一生成 diff 和
  `record.json`，不增加午夜分段、定时或读写、焦点事件检查点。
- 共享存储只约束路径、日期登记和删除生命周期，
  不能为提早提供记录而改变采集器的采集行为。

## 保留 Bash 记录行为

Bash 保留 history 输入记录语义：完整复合输入、history 开始时间、完成时间、
退出状态。命令的 `cwd` 是整条输入开始执行前的 shell 目录。
会话起止事件的 `cwd` 表示各自边界时刻的目录，每个事件只保留一个目录字段。
启用时立即写会话开始，正常退出时写会话结束。
不为每条命令重复添加会话 ID、PID 或会话开始元数据。
JSONL 不应因原生去重规则、前导空格过滤、HISTIGNORE、历史容量为零，
或关闭历史文件落盘而漏记命令。保留原生 history 内容与命令执行时的设置。
`set +o history` 目前仍是未解决的采集缺口。
已确认接受的历史编号限制和精简事件字段见 [Bash 说明](BASH.md)。

## 分析才使用工作日窗口

`config.json` 可设置 `day_start_hour`，例如 4。
它只影响提取与汇总，不出现在采集器的共享位置配置中。

分析 10 月 14 日 04:00 至 15 日 04:00 时，分析层按真实时间筛选记录。
Bash 和 Vim 读取器查找全部保留日期，因为相关会话可能在数月前启动。
截图读取器查找与分析窗口相交的拍摄日期。
按真实时间戳筛选，结束时刻不包含在窗口内。
一个自然日期目录可能服务于多次复盘。
不能仅凭目录名判断分析窗口，也不能从聚合 diff 推断每次编辑的精确时间。
长会话的最终 diff 无法可靠拆成逐日活动。
退出前已有原始快照，但还没有可供读取器使用的 `record.json`。
这一限制不能成为要求实时检查点的理由。

`daily/日期/_analysis/` 使用被复盘的日期标签保存中间材料，
这不改变输入原始记录的自然日归属。
正式报告仍放在 `memory` 或用户明确指定的长期位置。

## 采集器可独立使用

- Bash 采集器和独立 Vim 插件不要求先安装或初始化 My Big Brother。
- `C/raw-logs-path.txt` 是共享的一行 UTF-8 绝对采集根路径。
  缺失时，采集器使用平台数据目录下的 `daily`。
  Bash、Vim 和主项目的每日存储使用同一路径，文件格式错误时不能悄悄换目录。
- Bash 和 Vim 不读取 `storage.json`，也不维护日期登记。
  主项目通过 `storage.json` 确定长期数据根，为分析和受管理的写入维护最小日期状态。
  独立记录器不依赖这个运行时协议。
- Vim 仅在启动时依次选择 `record_dir`、纯路径 `C/raw-logs-path.txt`、
  平台数据目录下的 `daily`，不登记日期、不携带运行时协议副本。
  三种选择都采用 `YYYY-MM-DD/vim/<会话>/`，不兼容或迁移旧目录结构。
- 采集器不启动分析 Agent，也不读取其私人分析规则。

## 手动清理

用户可以直接删除已无活动任务的旧自然日期目录，不打开状态文件。
已登记但被移除的日期不能自动重建。正式记录和最小持久化事实保留。

一次复盘可能依赖窗口内的日期，也可能依赖更早的 Bash 或 Vim 会话启动日期。
只要会话仍在记录，其启动日期目录就仍属活动目录，即使会话已持续数月。
保留周期需覆盖仍在采集或分析的日期。
不能为实现清理而把分析工作日分界引入采集器。

具体接口见[存储说明](STORAGE.md)、[手动清理](CLEANUP.md)和
[输入来源](INPUT-SOURCES.md)。

## Python 实现基线

在不明显增加复杂度时，优先使用 Python 3.7 已有的语法和标准库 API，
不要只为写法新颖而引入更新版本的特性。
这是开发偏好，不是整个应用已兼容 3.7 的保证。
仍推荐 Python 3.11+，旧运行时未经单独测试就不能宣称支持。
针对采集器的局部修改不应扩展成无关的全仓库兼容性重写。
