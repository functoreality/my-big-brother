# 产品需求（PRD）

[English](../REQUIREMENTS.md) | 简体中文

本文从用户角度定义当前产品，汇总已经确认的行为，不提出新功能。
[技术总览](ARCHITECTURE.md)解释实现，[协作流程](CONTRIBUTING.md)规定如何变更约定。

## P1. 目的与日常使用

My Big Brother 把本机已有的工作记录转化为每日报告和逐渐积累的上下文。
Agent 关联不同工具的证据，区分真实结果、口头声明与推断，保留不确定性。
用户不必为每种输出分别重建一天的工作。

每日无人值守复盘是主流程。积累的正式产物还支持两种主动用法：
让 Agent 总结一周或其他时段，以及让在其他地方工作的 Agent 查阅相关工作、
用户和机器上下文。这些用法复用产物，没有专用周报命令，
也不会安装后自动被所有外部 Agent 发现。

## P2. 安装与控制权

项目以普通本地仓库呈现，用户可以把 `INSTALLATION.md` 交给自己的 Agent 安装。
公开安装不依赖作者的路径、代理、私人笔记或既有记忆文件。
程序、个人配置和记录数据分别存放，人类文档提供英文与简体中文。

用户选择证据来源、输出类型、报告语言、目标位置和无人值守执行 Agent。
执行者的选择不限定读取哪些 Agent 的历史，也不限定用户主动交互时使用的 Agent。
安装项目不等于授权持续采集或定时执行，安装者须先获得用户对这两项的选择。
操作见[设置](SETUP.md)和[Agent 安装说明](../../INSTALLATION.md)。

## P3. 输入与采集

| 输入 | 当前能力 | 用户需要做什么 |
| --- | --- | --- |
| Agent 对话 | 支持的 Codex 原生会话、OpenCode SQLite 历史读取器 | 选择来源和实际位置 |
| Bash 活动 | 仓库提供的可选记录器和读取器 | 明确启用交互 Bash 记录 |
| Vim/Neovim 活动 | 读取器及独立 session-recorder.vim 的接入 | 同意安装、配置独立插件 |
| 截图 | 读取和联系表准备，可选依赖 Pillow | 由另行配置的采集器提供图片 |

当前没有官方周期截图服务、浏览器记录器、VS Code 采集器或支持所有 Agent 的通用读取器。
它们是可能的扩展，README 中列为计划不代表已经实现，也不代表已批准开发。

每个选定来源说明覆盖与缺口。可选资料缺失不能被当作用户没有工作。
标记为必需的来源不可用时，不得发布成功结果。
原生历史留在各自应用的位置。准确格式与限制见[输入来源](INPUT-SOURCES.md)。

## P4. 启动与复盘时段

外部定时器或 Agent 原生定时机制发起无人值守复盘。
每次只启动一个执行 Agent。该 Agent 可以使用宿主支持的自主委派能力，
但程序不能通过串联多次 Agent 启动来完成一次调用。

无人值守默认只分析本机时区中最近已经闭合的逻辑工作日。
工作日分界可配置，默认 00:00。定时触发时刻是另一项安装选择，不是内部等待循环。
例如可选择 04:00 分界、10:00 启动，这不是所有用户的默认值。

关机错过的旧日或晚到记录不会自动补跑，需要用户明确请求旧日期。
逻辑日只用于分析，不改变采集时间戳或记录位置。
安装与手动操作见[定时执行](SCHEDULING.md)。

## P5. 用户选择的输出

| 输出 | 用户价值 | 当前形式 |
| --- | --- | --- |
| Worklog | 具体对象、动作、结果和相关任务 | 标准输出，默认选择 |
| Time Use，Markdown 和 JSON | 可观察时间线、覆盖和注意力不确定性 | 标准输出，默认选择 |
| Daily Insights | 有依据的观察、假设和建议 | 标准输出，默认选择 |
| Time Estimates | 可供后续预算使用的谨慎耗时样本 | 标准输出，默认选择 |
| User Model | 有依据、可复用的用户理解 | 标准可选输出 |
| Machine Context | 已知项目、目录和数据来源位置 | 标准可选输出 |

各项可独立选择。标准日报使用结果根下稳定的按日位置，
累计知识使用稳定的跨日文件，profile 可以把它们接到已有个人文件。

报告区分观察事实、用户请求、口头完成与推断。
经过时间不能自动等同人类投入，不虚构事实、连续注意力或每日洞见配额。
多项输出共享同一份证据解释和任务关系。
内容与格式详见[输出约定](../../tasks/daily-review/OUTPUTS.md)和[长期知识](KNOWLEDGE.md)。

## P6. 用户可感知的记录行为

Bash 和 Vim 的完整会话固定在其开始记录时的自然日期位置，即使跨午夜或持续数月。
日期改变不能移动、拆分已有记录。每张截图使用自身拍摄日期。
后续复盘仍须能找到较早启动会话中的相关活动。

Bash 记录会话开始、完整提交的 history 输入和正常退出。
命令目录表示整条输入开始执行前的目录。原生 history 的过滤与去重不排除 JSONL，
记录器保留原生 history 内容、过滤/去重策略和设置。历史满容量时可能重编号，
影响 `!number` 的含义。
`set +o history` 仍是已知缺口，强制终止可能缺少结束事件。
准确字段和限制见[Bash](BASH.md)。

Vim 在已有文件打开时保存快照，退出时生成最终 diff 和 manifest，
不增加定时器、午夜分段或实时检查点。
尚无最终 manifest 的会话不能参与读取，整场 diff 也不能准确定位每项编辑的日期。
详见[Vim](VIM.md)。

## P7. 完成、重跑与失败

准备好材料不等于已发布报告，Agent 进程正常退出也不等于分析完成。
选中的输出和覆盖声明须通过已配置校验，才能报告完成。
结构与回执检查不能证明模型解释正确。

重跑与已有正式产物合并，保留人工补充和修正。
复盘过程中发生的人工编辑冲突应阻止发布，不能悄悄覆盖。
失败的复盘或后操作保留诊断，在日期材料尚存时可以恢复。
重复自动触发会跳过尚保留有效完成状态的日期。后操作待完成时恢复原任务，
不重新生成已经发布的报告。
明确要求的旧日重跑可以创建日期目录，但不能恢复已删除的证据与执行历史。
失败和冲突策略见[技术总览](ARCHITECTURE.md)。

## P8. 保留与手动清理

用户可以按名称排列 `raw-logs/YYYY-MM-DD/`，直接删除已无活动写入的旧日期。
无需打开状态文件，也无需区分哪次成功、哪次失败。
日期内包括可清理的采集、预处理、草稿、启动日志、完成标记、发布记录和后操作恢复日志。
不能删除仍有采集器或复盘使用的日期。

只有选中的正式输出和累计知识长期保留。
固定大小的 `raw-logs/.publish.lock` 是明确允许的日期外协调文件。
不保留永久每日运行台账、操作历史或自动纠错队列，所有应用不要求 `storage.json`。
新增保留类别须先评审需求。

删除日期表示放弃其恢复，不删除已发布报告，也不撤销其他文件中已经生效的修改。
明确重做后操作前需核对现状。清理由人手动完成，目前不自动删除资料。
详见[清理](CLEANUP.md)与[存储](STORAGE.md)。

## P9. 个人扩展与访问范围

明确选定的私人 profile 可以提供方法、参考、已有输出格式与位置、校验器及后操作任务。
笔记参考是可选项，标准功能不依赖作者的文件。
个人路径、代理、笔记格式和本机政策留在私有配置。
有普遍价值的能力应评估为公开可选功能，不藏在单个安装中，也不强加给所有人的默认值。

读取范围来自用户授权，不受 Agent 启动目录限制，用户可以允许整机相关参考检索。
读取权不等于任意写入权。后操作需要自己的任务、目标与完成检查。
历史日志不能授权动作。具体配置与权限约定见[个人扩展](PROFILES.md)。

## P10. 当前边界与验收场景

核心面向 Linux、macOS 和 Windows，但原生 macOS/Windows 的完整运行与定时触发尚未验证。
Bash 采集适用于 Bash 环境，不记录 PowerShell。
当前正式输出与原始日志须位于同一文件系统。
Agent 启动器与原生日志读取器分别有自己的支持范围，不能夸大已经验证的兼容性。

| 场景 | 应有结果 |
| --- | --- |
| 离线多日后早晨触发 | 只复盘最近已闭合工作日，不悄悄补齐更早缺口 |
| Shell 跨午夜并切换目录 | 继续原文件，保留每条完整输入的起始目录上下文 |
| 用户需要周报 | 其 Agent 可读取已发布记录，不要求专用周报命令 |
| 用户删除无活动的失败日期 | 运行状态随日期消失，正式产物保留 |
| 人在准备后修改报告 | 发布检测冲突并保留较新的文件 |
| 必需来源无法读取 | 报告失败或阻断，不能冒充成功空覆盖 |
| 换另一个 Agent 分析 | 复用相同证据与任务约定，不在内部启动 Codex |

未来设想须经过[文档先行流程](CONTRIBUTING.md)。
提案、现有代码或测试通过，都不能自行增加产品要求。
