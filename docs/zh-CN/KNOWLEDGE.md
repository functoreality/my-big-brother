# 长期知识输出

[English](../KNOWLEDGE.md) | 简体中文

两类标准输出可在多次复盘间保留有用背景，任何执行 Agent 都可以使用，
无需私人任务或记忆服务。新安装与四类日报输出一起默认开启，用户可独立关闭。
已有配置中明确选择的输出保留，不因升级自动补回。

| `config.json` 输出名 | 输出类型 | `results_root` 下的默认位置 |
| --- | --- | --- |
| `user-model` | `user_model` | `USER-MODEL.md` |
| `machine-context` | `machine_context` | `MACHINE-CONTEXT.md` |

默认 `outputs` 数组包含全部六类标准输出，移除名称即可关闭对应输出。
完整标准输出列表与重定向 JSON 示例见[英文版](../KNOWLEDGE.md)。
保留配置中的其他字段。

执行 Agent 读取共享的[知识契约](../../tasks/daily-review/KNOWLEDGE.md)，
沿用日报的证据分析。程序不会为此启动额外 Agent，也不会主动盘点本机。

无人值守复盘只处理最近一个已闭合逻辑日。
用户明确要求重跑多个旧日期时，按日期从旧到新执行 `analyze --date YYYY-MM-DD`，
完成该日发布和后操作后再准备下一天，确保新草案使用最新累计知识。
不会自动排队处理历史日期或恢复错过的日期。

User Model 记录相关目标、约束与明确表达的偏好。
Machine Context 记录已知机器、文件、目录与资料来源位置。
两者均应区分用户明确陈述、观察和不确定推断，保留日期、依据与适用范围。
历史中提到某条路径，不能证明它现在存在，也不构成读取授权。

准备复盘时，程序将已有知识文件复制到暂存草案，包含人工补充。
Agent 合并有依据的更新，保留既有知识和用户纠正，避免重跑时重复追加。
没有可靠新事实时，可保持已有草案不变。
新文件可简短说明尚未建立有依据的知识。

`finish` 将知识草案与日报一起校验发布。
正式目标在准备后发生冲突修改时，会阻止过期内容发布。
应重新准备复盘，再合并最新版本。
运行草案保留该轮提交的版本。
默认保留已有文件权限，除非 profile 明确覆盖。
后续累积知识更新不会使先前已完成日期失效。

改变选中的输出类型时，该日期需要重新复盘，即使两类共用的最终文件没有变化。
完成跳过与待执行动作恢复会核对保留运行上下文中的逻辑选择，
选择不符或上下文无法核实时，不复用旧运行。

## 知识写到哪里

安装 Agent 按“用户明确要求及已有绑定 → 每日分析 Agent 已维护的合适文档
→ 项目默认双文件”的顺序选择。
应核对实际用途、所属工作区、宿主维护规则和写入方式，
`USER.md`、`TOOLS.md`、`MEMORY.md` 等名称只是线索。
安装者与每日分析者不同时，应为每日分析者选择位置，不默认复用安装者的私人记忆。

能明确判断的情况由安装 Agent 决定，并告知最终路径及是否共享文件。
用途或取舍不明确时再询问用户。已有明确选择须保留，路径绑定后不会每天重新发现或切换。
需要专用 API 维护的记忆库不自动当作 Markdown 文件接入，
安装者应说明限制，改选合适文档或项目默认位置。

如需使用已有文件，在选定的[本地 profile](PROFILES.md) 中设置
`output_paths.user_model` 和 `output_paths.machine_context`。
这两类 Markdown 绝对路径不要求 `{date}`。
是否准备和发布仍由 `config.json` 的 `outputs` 控制。
无需 Codex 专属绑定或自定义日报后任务，其他私人参考资料仍由 profile 明确限定。

两类知识独立启停，不要求分成两个文件。
两个路径键可以绑定同一份合适的 Markdown，例如 `/example/workspace/MEMORY.md`。
两类均开启时，只准备一份完整合并草稿，`finish` 只发布一次，完成收据也只列一次暂存路径。
保留文档原有组织、无关内容、宿主指令和人工纠正，遵守宿主篇幅及维护约定，
避免把长期记忆变成每日流水账。

关闭一类只停止更新该类内容，不删除共享文档中的既有信息，另一类仍可继续更新。
自定义校验程序需支持[个人配置](PROFILES.md#输出校验)中的共享映射。
共享只适用于这两类累计 Markdown，不适用于日报或 JSON 输出。
