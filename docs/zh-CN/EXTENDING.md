# 扩展 My Big Brother

[English](../EXTENDING.md) | 简体中文

核心程序准备证据并管理一次复盘。
Agent 阅读 Markdown 任务说明，主导分析。
新增功能应放在对应的一侧，而不是把每一步语义分析都转成程序流程。

## 四个独立的扩展点

| 组件 | 职责 | 示例 |
| --- | --- | --- |
| 采集器 | 在宿主应用中记录活动 | Bash 钩子或未来的编辑器插件 |
| 输入适配器 | 读取记录，准备带索引的证据 | Codex JSONL 或 OpenCode SQLite |
| 分析任务 | 说明如何理解证据，以及希望得到什么结果 | 每日复盘或未来的每周复盘 |
| 分析器启动器 | 启动一个无人值守的 Agent | Codex CLI 或未来的其他后端 |

Codex 作为输入源，与 Codex 作为分析器启动后端，是两个独立的集成。
用户可以添加输入源，而不更换已选择的分析器。
较重的编辑器插件可以在独立仓库发布，
本仓库则维护它的输入适配器和集成说明。

## 添加输入

在 `my_big_brother/sources/` 中创建模块，实现：

```python
def collect(path: Path, start: datetime, end: datetime) -> SourceResult:
    ...
```

`SourceResult` 包含 `rows`、`status` 和 `gaps`。
状态使用 `ok`、`partial` 或 `unavailable`，
返回时间位于 `[start, end)` 内、按时间戳排序的记录。
记录包含带 UTC 偏移的 ISO 时间戳，并保留输入源特有的字段。
会话记录应包含角色和内容。
通用准备逻辑把可读的内容摘录与精简索引分开保存。

在输入源选择代码中注册适配器，添加对应配置、任务输入规则和合成格式测试。
目前采用显式注册，没有第三方插件加载器或统一的活动数据结构。
请说明支持的版本，并把解析失败表示为证据覆盖缺口。

读取上游历史时，不要修改原始文件。
新增采集器应遵循共享的 `C/raw-logs-path.txt` 位置约定，
写入 `raw-logs/YYYY-MM-DD/<source>/`。
目录使用自然日期，记录自身带时间戳。
采集器不读取 `results_root`。

## 添加输出

对于基于同一天共享证据、时间线和任务划分的结果，
扩展每日任务的输出约定。
在核心程序中添加输出名称、稳定的保存路径和必要的校验。
复用已有的统一分析，不要为每种输出重新独立分析全部证据。

结构化输出需要说明数据格式，并进行有意义的校验。
供人阅读的输出需要清晰的内容边界和重跑规则。
应定义如何保留用户编辑，并避免重跑产生重复内容。

目的或时间范围不同的任务，可以使用自己的任务目录。
未来的每周复盘通常会读取已发布的每日记录，
而不是重新处理一整周的原始会话。

## 添加 Agent 启动入口

只有启动边界需要知道具体 Agent 的可执行文件、登录、沙箱和超时。
用共享的[自动化任务](../../tasks/daily-review/AUTOMATION.md)启动一次 Agent，
提供安装目录、Python、日期或回看范围，以及允许访问的位置。
由 Agent 自己调用通用准备、发布和回执校验，也完成已配置的后操作。
不要把 Agent 调用放进 `runner.py`、输入适配器、校验器或共享 CLI。
原生定时 Agent 可以直接使用相同任务，不需要额外启动器。

安装 Agent 可以根据本机执行接口编写入口，不确定时查询本机帮助或官方文档。
内置示例是 `python -m my_big_brother.analyzers.codex`。
新入口可保存在安装仓库之外，也可作为 PR 加入 `analyzers/`。
按通用运行状态检查实际完成情况，不能只看进程退出码。
不要在每个入口里复制分析算法，或自动另启 Agent 执行后操作。

## 用户自定义任务

用户可以在 `C/local-tasks/` 保存 Markdown 指令，
不需要修改安装的标准任务。
程序不会隐式发现其中的文件。
明确选择的[个人配置档案](PROFILES.md)可以加载复盘规则、声明参考资料，
绑定输出和校验器，并配置单独限定范围的复盘后任务。
用户也可以直接把指令交给当前 Agent。
每个扩展都应定义输入、写入位置、权限和重试行为。

配置的任务可以维护长期知识、编辑用户指定文件或发送通知。
这类操作需要明确的目标和重跑规则。
不能因为报告重新生成，就再次发送相同通知。
应分别记录报告完成状态和后续操作状态。

需要稳定行为时，可以添加小型、确定性的辅助程序。
在有具体需求之前，不必先搭建通用任务框架。
