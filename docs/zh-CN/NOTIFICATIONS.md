# 本地主动提醒

[English](../NOTIFICATIONS.md) | 简体中文

每日复盘发现值得你关注的问题时，My Big Brother 可以留下一条本地 Markdown 消息，
例如已经验证的错误、影响后续工作的遗漏，或需要你作决定的具体问题。
公开任务提供筛选规则和投递工具，无需自行编写私人提醒任务。

新安装默认开启，消息放在 `results_root/inbox/`。
运行 `python -m my_big_brother paths`，可查看解析后的 `notifications` 设置。
安装 Agent 应告诉你实际位置。打开这个目录即可阅读消息，也可以接入自己的查看流程。
默认生成文件，不发送邮件、聊天推送或桌面弹窗，也不直接修正原文件。

## 改位置或关闭

修改已有 `config.json` 中的 `notifications` 项：

```json
"notifications": {
  "enabled": true,
  "inbox": null
}
```

`null` 使用 `results_root/inbox/`。需要改位置时，将 `inbox` 设为绝对目录路径，
且不能与可清理原始日志存储重叠。关闭时将 `enabled` 设为 `false`。
不需要个人 profile 或自行配置校验器。
执行 Agent 必须有该目录的写入权限。附带 Codex 启动器会纳入所选收件目录，
其他启动器也须授予该目录权限，不能为了方便扩大到不必要的父目录。

已有配置没有 `notifications` 字段时保持关闭，升级不会自动开启，
也不会因此重复私人通知。需要启用时显式加入上面的配置项。
如果个人 `post_review` 已有类似提醒，先决定由哪个任务负责，再启用两者。
通用提醒阶段先执行，之后才执行另外配置的私人后操作。

## 什么值得提醒

Agent 核对依据，只在预期收益超过打扰成本时留言。
每条消息说明问题、触发证据、预期收益、置信度、限制和最小下一步，
使用报告语言，并指出可长期定位的报告或用户对象。
没有每日条数要求，没有合格提醒时正常完成。
一般工作总结或每一条每日洞察不必另发提醒。
Agent 可能遗漏错误，也可能判断不准确。校验能检查结构和投递内容的一致性，
不能保证语义判断正确。

[真实笔记纠错案例](../../examples/real-cases/fid-note-correction/README.zh-CN.md)
展示了这种价值。那次历史运行实际使用的是私人通知任务。

## 完成与重试

报告发布后，同一个复盘 Agent 负责提醒。
`finish` 返回 `actions-pending` 和 `<review-run>/notifications/` 中的任务提示。
Agent 阅读公开[任务](../../tasks/notifications/TASK.md)，检查已有消息，
暂存 Markdown 草稿与 `messages.json`，调用上下文中的准确 `delivery_command`。
投递成功后才写操作回执，再调用 `finish`。
若接着返回私人后操作，继续在同一会话中完成并再次调用 `finish`。
只有最终 `completed` 才表示整次复盘完成。

消息使用 `DATE--STABLE-ID.md` 文件名。任务按实际问题检查已有提醒，
包括其他日期，没有实质变化不重复发送。
投递工具不覆盖消息，同名相同内容视为已投递，不同内容会阻止投递并保留现状。
保留人工修改，不得通过更换 ID 绕过冲突。

失败时日报保持已发布，操作仍待处理。
恢复同一运行，先检查计划和已有目标，查明差异后再重试。
中断可能留下不完整消息，需要人工诊断，不自动替换。
计划和回执留在可清理日期内，正式消息留在长期收件目录。
删除旧运行材料不会移除消息，明确重跑仍须检查实际收件箱，避免重复。
不建立永久投递队列。
