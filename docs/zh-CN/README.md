# 文档地图

[English](../README.md) | 简体中文

My Big Brother 用一个执行 Agent 复盘选定的本地活动，生成日报与可选累计知识，
把可清理材料集中在日期目录。本文区分产品承诺、实现方案和变更共识的方式。

## 三份核心文档

| 文档 | 总体概括 | 何时阅读 |
| --- | --- | --- |
| [PRD](REQUIREMENTS.md) | 用户控制权、输入输出、单日无人值守、手动重跑、保留、个性化及当前边界 | 理解或提出产品行为变化 |
| [技术总览](ARCHITECTURE.md) | 采集/读取/任务/启动的职责，路径时间模型，暂存发布，锁、冲突与恢复 | 理解或提出实现手段变化 |
| [文档先行流程](CONTRIBUTING.md) | 区分落实旧约定与新提案，讨论同意、更新文档后再实现验证 | 任何实现任务或评审驱动改动之前 |

PRD 和技术总览不要求读者打开所有链接才能看懂全貌。
它们负责总体概括，细节文档只负责该范围内的准确格式和协议，不能另起一套产品政策。

## 权威性与变更状态

- 用户/维护者决定范围，新决定先写入所属文档，再进行依赖它的实现。
- 当前 PRD 和技术约定指导实现，代码、测试和执行指令应对齐它们，不能悄悄改约定。
- 提案经明确接受并整合到现行文档前，不是当前约定，计划清单也不是批准。
- 审查和实验记录证据，历史方案即使写过“已批准”，也不代表仍是当前约定。

发现冲突时，指出差异，不能只选离自己最近的文件，也不能把现有代码当作产品决定。
按[变更流程](CONTRIBUTING.md)处理。
翻译保持相同范围和编号，英文任务、命令名和 JSON schema 共享一份规范。
公开地图不承担个人部署或迁移的权威记录。
