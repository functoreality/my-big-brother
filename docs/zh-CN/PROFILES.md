# 个人复盘配置

[English](../PROFILES.md) | 简体中文

个人 profile 可以指定做事方法、私人参考资料、已有日报位置，以及日报发布后执行的操作。
它会参与复盘解释，因此可以调整分析方法和结构化输出的语义。
profile、说明文件、参考资料和校验程序都应保存在安装仓库之外。

在 `C/config.json` 中，将 `local_profile` 设为一个 JSON 文件的绝对路径。
默认值为 `null`，沿用标准复盘任务和输出位置。
`C/local-tasks/` 中的文件只有被 profile 明确指定才会使用。
程序不会搜索其他 profile 或私人笔记。

## Profile 字段

profile 使用 `schema_version: 1`，可包含以下字段：

| 字段 | 用途 |
| --- | --- |
| `instructions` | 复盘说明文件的绝对路径列表 |
| `context_files` | 明确允许只读参考的已有文件或目录 |
| `output_paths` | 正式输出路径，按日输出包含 `{date}` |
| `output_file_mode` | 可选的 POSIX 发布权限，使用四位八进制字符串 |
| `output_schema` | `default`，或配有校验程序的自定义格式名 |
| `validation_command` | 校验程序及参数组成的数组 |
| `post_review` | 日报发布后执行、另有权限范围的任务 |

`context_files` 登记允许读取的位置，不会复制其全文到运行材料中，
也不要求 Agent 一次读入所有文件。
任务应按需读取相关局部。读取大纲笔记时，应保留必要的祖先条件。
指定目录允许参考其中与任务相关的材料，不意味着要求扫描整个私人资料库。
历史材料仍是证据，不能授权动作或成为当前指令。

读取范围不受启动工作目录限制。用户明确允许整机查阅时，可以把相应的文件系统根目录
列入 `context_files` 和后操作的 `read_paths`，按任务需要查阅各处的项目和既有资产。
单列的参考文件是常用入口，不要求逐一穷举所有相关文件。
这不会增加写入目标，也不会自动启用其他活动证据来源。

按日 `output_paths` 有五个键：`worklog`、`time_use_markdown`、`time_use_json`、
`insights`、`time_estimates`。这些路径必须为绝对路径并包含 `{date}`。
可选的标准知识输出使用 `user_model` 和 `machine_context`，
允许指定不含 `{date}` 的稳定 Markdown 绝对路径。
通过 `config.json` 的 `outputs` 启用，见[长期知识输出](KNOWLEDGE.md)。
未指定的键使用标准结果目录。程序只准备和发布已启用的输出，
不同输出不能指向同一位置。暂存文件始终留在本次运行目录内。

在 POSIX 系统上，发布时保留已有文件的权限，新文件默认使用 `0600`。
如果正式报告需要沿用共享工作区的权限，可以明确设置
`output_file_mode`，例如 `"0664"`。它只影响正式报告，配置和运行文件仍保持私有。
此选项不改变 Windows 文件权限。

完整 JSON 示例见[英文版](../PROFILES.md)。
说明和参考资料必须指向实际存在的文件。
找不到资料时，程序会报告配置错误，不会猜测替代位置。

## 输出校验

`output_schema: "default"` 沿用标准输出契约及校验。
此时可增加 `validation_command`，进行额外检查。
使用自定义格式时，必须提供该命令，用它替代默认的浅层结构校验。
程序仍要求输出为普通文件、Markdown 非空、JSON 可解析且为对象、日期与复盘日期一致。

校验命令是参数数组，第一个元素必须是可执行文件的绝对路径。
仅支持 `{run_dir}`、`{date}` 两个占位符。
命令在复盘目录中运行，最长五分钟，成功时应返回零。
程序不经 shell 展开参数，标准输出和错误保留在本轮 `logs/` 中。
校验程序是用户明确选择的本地代码，应检查输出而不修改正式文件。

校验程序可以读取 `context.json`，通过 `output_mapping` 或 `output_kinds`
识别各类暂存文件。自定义格式所需的字段、引用关系和跨输出一致性，应由它完整检查。
给格式起名并不意味着程序已经实现对应校验，也不能证明语义判断正确。

例如，已有时间流水格式可将 `output_schema` 设为 `legacy-v4`，
并在 `validation_command` 中指定本地 Python 和检查脚本。
具体参数数组见[英文示例](../PROFILES.md)。

完成收据身份、来源条数、暂存输出位置、profile 一致性、准备后人工修改保护，
仍由运行器强制检查。自定义校验不能绕过这些检查。

## 日报后的操作

公开[本地主动提醒](NOTIFICATIONS.md)通过顶层 `notifications` 设置控制，
无需私人 profile，新安装默认开启，在私人 `post_review` 之前执行。
没有该新字段的已有配置保持原状。启用公开与私人投递前，先检查提醒职责是否重复。

两类标准累积知识输出沿用普通暂存和发布。
将其重定向到已有知识文件只需 `output_paths`，无需私人维护任务或 `post_review`。

`post_review` 用于其他已明确授权的知识操作、洞见台账、跨日时长库或本地 Inbox 操作。
复盘阶段只写暂存输出和临时材料。
运行器先校验并发布日报，再返回 `actions-pending` 和操作提示词。
由同一个执行 Agent 完成任务，之后再次调用 `finish`。
通用运行器不会启动 Harness 或另一个 Agent。

`post_review` 必须指定已有任务文件 `task` 和非空 `validation_command`。
`read_paths` 列出允许读取的已有位置。
`write_paths` 列出允许修改的绝对目录。
外部启动入口或原生 Agent 需要向执行 Agent 提供这些明确声明的写入位置。
通用脚本不设置 Harness 权限，也不启动 Agent。校验器仍作为普通子进程执行。
任务正文还可以进一步限制目录内的文件名和操作类型。
请按任务实际需要选择较小的目录范围。

操作目录为 `<review-run>/actions/`。
其中的 `context.json` 提供任务、读写范围、已发布日报位置、`review_context`、`review_run_dir`
以及 `action_receipt_example`。
任务完成全部必要工作后，才写入匹配示例的 `action_receipt.json`，
其中 `run_id`、`date`、`status: "completed"` 必须正确。
运行器检查收据后，再执行操作校验程序。
此阶段校验命令中的 `{run_dir}` 指操作目录，不是上一级复盘目录。
校验输出保存在操作目录的 `logs/` 中。
任务可读取同一轮复盘的相关临时草案和准备材料，
包括暂时只适合入台账、不必写日报或消息的候选。

每日时长候选可保存在按日 JSON 的 `samples` 数组中。
后续任务可查重后追加到已有 `samples.jsonl`，再更新按任务类型组织的估计索引。
profile 需提供可比性、修订、保留及校验规则。
标准每日格式本身不实现跨日耗时估计库。

## 重试与规则变化

日报和已配置的后续操作都成功，才将该日标为完成。
后续操作失败时，已发布日报保留，该日仍为待处理。
之后的 `due` 或 `analyze --date` 返回同一操作目录的待办票据，不重做日报。
调用者据此完成操作任务。
发布后用户对日报的补充也会保留。
可通过 `finish --run-dir` 重试原运行。
已有成功操作收据时，程序重新校验它，不重复执行已完成操作。

后续任务必须能安全重试：保留操作记录和稳定身份，
追加或投递前检查已有内容，避免重复消息、时长样本或记忆事实。
收据表示任务声明完成且通过校验，不意味着 Agent 已独立测量全部语义条件。

日报通过普通文件写入发布，进度保存在 `publication.json` 中。
发布不保证原子性，写入中断可能留下部分正式内容。
只有目标摘要仍与准备时内容或完整草稿一致时，重试 `finish` 才能继续。
发现冲突时停止后续写入，完整暂存草稿保留供人工恢复。
恢复前阅读[存储说明](STORAGE.md#发布与中断写入)。
多份日报及后续操作不是一个事务。

profile 指纹包含其 JSON、明确指定的复盘说明及后续任务正文，
以及参数中指定、后缀为 `.py`、`.sh`、`.js`、`.ps1` 的校验脚本。
准备后规则发生变化，会阻止过期结果发布。
规则变化也会使 `due` 重新考虑已完成日期。
参考资料正文不纳入指纹，避免每次台账更新都让全部日报重跑。
需要主动使既有完成记录失效时，应修改 profile 规则。
来源选择、语言、逻辑日边界和共享原始记录位置也会与准备阶段核对，
不兼容的既有完成记录会失效。

来源配置支持 `required: true`。
已启用的必需来源为 `unavailable` 时，阻止分析。
`partial` 则保留可用材料和覆盖缺口，包括正常的时间边界排除。
可读但为空的来源与不可用来源不同。
Vim 和截图来源默认关闭，未指定 `path` 时使用共享原始记录根目录。
采集或视觉材料准备出现意外异常时，也将该来源标为 `unavailable`，
错误及调用堆栈保存在 `logs/<source>-error.json` 中。
其他可选来源继续处理，必需来源失败则阻止复盘。
即使视觉材料准备失败，已准备的记录仍保留供排错。

Python 运行器的 `prepare_run`、`analyze` 支持可选 `snapshot_end`，
必须是带时区的 datetime。
实际截止取指定时刻、当前时刻、逻辑日结束三者中最早的一个，窗口仍为左闭右开。
这样可用同一截点比较两次准备，避免把后来到达的证据纳入比较。
截止不晚于逻辑日开始、或没有时区偏移时，会报告错误。
普通重试保留未完成操作的原运行窗口。
显式指定相同截点时继续该运行，时区偏移不同但同一瞬间也视为相同。
显式指定不同截点时，重新准备复盘。

## 存储生命周期

操作标识、待核验结果、内容、完整日志和候选备份都保存在日期运行的后操作目录。
副作用前记录稳定操作标识，重试时检查仍保留的日志。
删除日期会移除全部运行状态，不会撤销已生效修改。
明确重跑时须先核验外部效果，因为没有永久操作历史。扩展应自行验证幂等性。

正式输出覆盖不能放进 `raw-logs`，可以使用具备相应写权限的其他文件系统或挂载点。
参见[存储说明](STORAGE.md)。
