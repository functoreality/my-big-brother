# 手动清理

[English](../CLEANUP.md)

运行下面的只读命令找到 `raw-logs`：

```sh
python -m my_big_brother paths
```

在文件管理器中打开它，按名称排序，选择已无活动写入的旧 `YYYY-MM-DD`
目录，直接删除。无需打开任何状态文件，也不用区分分析成功或失败。
需要释放空间时，再清空回收站。

一天的原始记录、`_analysis` 下的索引、摘录、截图拼图、草稿、
临时脚本、后操作材料，以及 `_launches` 启动日志都属于日期目录。
删除整日即可清理这一单元。
原始记录的日期按系统自然日计算，与 04:00 等复盘分界无关。
Bash 和 Vim 跨日会话始终保存在启动日期下，因此一次复盘也可能依赖更早日期，
不只依赖窗口覆盖的相邻两天。最终会话 diff 不能精确按日期拆分编辑活动。
分析材料仍使用被复盘的日期标签。
不要删除正在采集或复盘的活动日期，
包括仍有 Bash 或 Vim 会话正在记录的较早启动日期。
只要长驻 shell 仍在记录，即使其目录已有数月也仍属活动目录。

完成标记、发布日志、后操作日志和证据、运行材料一起删除，无法继续恢复该运行。
已发布报告、累计知识和已生效修改保留，其他位置没有需要保留的永久逐日状态。

无人值守复盘只考虑最近一个已闭合逻辑日，不排队处理更早日期。
需要重跑旧日期时明确使用 `--date YYYY-MM-DD`，可以创建该日期的工作区，
但不能恢复已删除的证据或操作日志。重复操作前须核验外部效果。
新的采集会话使用自身创建日期，采集辅助命令无需保留日期登记即可创建自然日目录。

保留 `memory` 中的正式报告、第一层长期知识和 `records`，以及配置、个人任务。
个人 profile 可能将正式文件放在其他长期位置，删除临时日期不影响这些正式产出。
保留固定大小的 `raw-logs/.publish.lock`，它只协调发布，不包含日期历史。

删除原始证据会限制未来重跑，低分辨率拼图不能替代原始截图。
Agent 原生会话历史属于对应应用，不由本项目删除。
