# 手动清理

[English](../CLEANUP.md)

本版本不会自动清理原始日志或运行材料。
已完成分析的运行目录可以清理，正式输出可以继续保留。
请在复盘之间操作，等执行 Agent 停止、复盘后操作及纠错确认全部结束。

## 找到实际路径

在仓库目录中，使用安装时的 Python 环境执行：

```sh
python -m my_big_brother paths
```

查看返回的 `raw_logs`、`state`、`results` 和 `config`。
个人数据不放在源代码仓库中。
Linux 默认数据目录是 `~/.local/share/my-big-brother/`。
macOS 和 Windows 以命令实际返回的位置为准。
个人 profile 可以将正式输出重定向到 `results` 之外。
清理前查看 `profile.output_paths`，或运行 `context.json` 中的
`final_output_paths`，确认正式文件的位置。

| 位置 | 内容 | 手动清理方式 |
| --- | --- | --- |
| `raw_logs/YYYY-MM-DD/` | 按自然日归档的应用采集记录 | 不再需要旧输入、没有程序继续写入、相关复盘已完成后，清理旧日期 |
| `state/runs/日期/运行ID/` | 索引、摘录、截图拼图、草稿、脚本、日志、收据及可选 `actions/` | 完成分析和最终确认后整轮清理，或明确放弃已停止的未完成运行 |
| `state/launches/启动ID/` | 启动上下文、Agent 日志、日期票据和整轮收据 | Agent 已停止、整轮完成后清理，失败轮次先排错或明确放弃 |
| 调度日志，通常为 `state/scheduler.log` | 持续追加的启动输出 | 在两次调度之间归档或清空旧内容 |
| `state/completed.json` | 用于跳过已完成日期的台账 | 保留 |
| `state/locks/` | 协调运行的锁文件 | 保留，尤其不能在程序运行时清理 |
| 其他个人配置或导入状态 | 队列、去重和恢复信息 | 除非扩展自身说明允许清理，否则保留 |
| 正式结果及个人 profile 的目标文件 | 日报、累计知识及持久化后操作产出 | 保留 |
| 配置及安装的个人任务 | 设置、路径定位文件、任务说明 | 保留 |

Agent 原生会话历史仍位于各个 Agent 自己的目录。
它们是输入，不是本项目拥有的临时副本，请按所属应用的保留方式管理。

## 清理旧的原始记录

在文件管理器中打开 `raw_logs`，按日期目录名称排序。
检查旧目录后删除，或先移到所有已配置输入根目录之外归档。
移入回收站后还需清空回收站，才会释放空间。
只在同一磁盘移动归档不会释放空间。

不能只按目录名称判断是否可以删。
旧 Bash 会话可能持续写入会话启动日期目录，Vim 会话也可能很晚才结束。
不要删除仍被终端、编辑器或采集器使用的目录。
复盘窗口可能跨两个自然日，例如 04:00 至次日 04:00。
删除一个自然日之前，还要检查相邻复盘窗口是否仍需其中的数据。

删除输入不会删除已发布日报，但会限制未来重跑和纠错。
截图拼图分辨率较低，不能代替原始截图。
部分 Vim 证据也只是引用源文件，没有完整复制到运行目录。

## 清理旧的分析运行

1. 打开 `state/runs/`。第一层是**复盘日期**。
   每个日期下面的运行 ID 以准备时间开头，后面是随机后缀。
   补做历史日期时，运行 ID 可以是最近才生成的。
2. 查看每轮的 `state.json`。
   `completed` 表示该轮的发布和已配置的后操作校验均已完成。
   再检查 `context.final_output_paths` 中的正式文件仍然存在。
3. 确认没有 Agent 正在使用该轮，也没有未结束的整轮调度或个人纠错确认依赖它。
4. 可以删除整个运行 ID 目录，其中的索引、摘录、拼图、草稿和 `actions/` 一起删除。
   若要删除整个日期目录，先逐一检查里面的所有运行。

`prepared`、`empty`、`blocked`、`actions-pending`、`actions-failed`
都不表示复盘已完成。
仅有 Agent 写的 `completion.json`，或启动状态显示 `agent-exited`，也不够。
未完成轮次应保留用于恢复，或者等相关程序全部停止后，明确决定放弃它。
删除 `actions-pending` 的运行目录，会破坏该轮自动恢复后操作所需的材料。

保留正式文件和 `state/completed.json` 后，日常跳过已完成日期不要求旧运行目录存在。
台账中的旧路径可以作为历史元数据保留。
删除后不能再原地恢复或重新校验那一轮。
显式重跑会创建新的运行目录，并需要足够的保留输入。
自定义扩展可能另有对旧运行的依赖，先检查其任务说明。

## 清理启动记录和其他副本

启动 ID 是随机值，不包含日期。
打开启动目录的 `state.json` 查看 `updated_at`，
再从 `automation-context.json` 或 `tickets.json` 查看处理了哪些日期。
共享自动化流程成功时，`automation-result.json` 应为 `status: completed`。
`agent-exited` 单独只说明进程退出。
整轮结束或明确放弃之后，可以清理整个启动目录。
Agent 仍在写日志时不要删除。原生 Agent 调度器可能另有自己的执行历史。

旧安装备份、测试目录和旧采集器目录也可能占用空间。
它们不是日报格式必需的内容，但可能用于回滚、导入和恢复，应单独核对。
仍启用的导入器可能从保留的旧源重新生成已删除的原始记录。
只删除导入后的副本，不能实现永久的保留期限。

保留应用数据根目录和 `state` 根目录。
不要为了清理中间产物而整体清空 `state`、配置、正式结果或个人知识目录。
