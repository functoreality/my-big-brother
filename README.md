# My Big Brother

English | [简体中文](README.zh-CN.md)

**THE BIG BROTHER IS WATCHING YOU!**

**EVERY DAY!**

**ON YOUR COMPUTER!**

And... taking notes for your next weekly report.

Meet your AI big brother: every day, he reviews the work you've recorded,
connects the evidence, and leaves useful reports and context for tomorrow.

The idea is simple: local activity records become a daily review, and daily
reviews accumulate into a memory of your work. Start with an unattended review
each day. Keep the outputs useful for decisions, reflection, planning, and
other Agent conversations, instead of making every report an isolated diary.

You choose the sources, outputs, and Agent. My Big Brother prepares evidence
and manages checked publication. The Agent interprets the records and can
maintain selected long-term context through an explicit personal profile.
Collectors use natural system dates. Working-day boundaries belong only to
analysis. See the [collection requirements](docs/REQUIREMENTS.md).
Collectors record activity separately. Installing this project does not start
screen capture or recording in every application.

See a [synthetic example](examples/synthetic/README.md) generated by a real
Agent run. The project is an ordinary local repository, without a service,
Skill, or MCP server.

## Inputs

Status: **Available** is shipped, **Planned** is proposed follow-up work.
Planned items have no promised delivery date. Readers and collectors are
separate capabilities, as noted below.

- **Agent conversations:** **Available** native Codex session files and
  supported OpenCode SQLite history. **Planned** readers for more Agents.
- **Software activity:** **Available** Bash records with an optional bundled
  recorder, and Vim/Neovim sessions collected by the separate
  [session-recorder.vim](https://github.com/functoreality/session-recorder.vim)
  plugin. **Planned** VS Code and additional application collectors/readers.
- **Periodic screenshots: Planned.** An official periodic capture tool and
  portable capture setup are not yet provided, so recording is not ready to
  start out of the box. If your own collector already takes periodic captures,
  **Available** readers can process those images and generate contact sheets
  with optional Pillow. Neither installation nor the reader starts capture.
- **Browser activity:** **Planned** collection and reading of browsing records.

Have another source in mind? Open an [issue](https://github.com/functoreality/my-big-brother/issues)
or send a [PR](https://github.com/functoreality/my-big-brother/pulls).
See [Input sources](docs/INPUT-SOURCES.md) for formats and coverage boundaries.

## Outputs

**Via profile** means supported through explicitly configured personal tasks
and destinations, rather than enabled as a standard output for everyone.

- **Daily records:** **Available** Worklog in Markdown and Time Use in
  Markdown and JSON.
  They preserve outcomes, evidence gaps, and unknown human attention.
- **Reflection and planning:** **Available** Daily Insights and conservative
  duration samples. Each standard output can be enabled independently.
- **Long-term understanding:** **Available** optional User Model and Machine
  Context outputs, retained directly under `memory/`. The same daily Agent
  maintains supported user preferences and known file/directory/source locations.
  A profile can redirect them to existing files. See [Knowledge](docs/KNOWLEDGE.md).
  **Via profile** additional project-specific knowledge and operations.
- **Follow-up actions:** **Via profile** maintenance of selected local files
  and cumulative records. Notification tasks can be configured with their own
  delivery helper and validator. **Planned** reusable action presets.

Suggest another useful output through an
[issue](https://github.com/functoreality/my-big-brother/issues) or
[PR](https://github.com/functoreality/my-big-brother/pulls).
[Personal profiles](docs/PROFILES.md) define references, output bindings,
validation, write scope, and retry behavior.

### Use the accumulated outputs

These are two ways to use the context built by daily reviews:

1. **Summarize your work:** start an Agent in this repository and ask it to
   read published daily records for a weekly report or project recap.
   This uses your current Agent, without a built-in weekly-report command.
2. **Bring context to another conversation:** tell an Agent in another project
   where My Big Brother is installed. Let it use `paths` to locate relevant
   reports and any explicitly configured user or machine-context notes.
   Installation alone does not share these files with every Agent, and the
   standard daily outputs do not create a complete machine inventory.

Both build on retained outputs. They do not replace the daily review or
require reprocessing every capture.

## Get started with your Agent

Copy this message to an Agent that can work on your machine:

```text
Install https://github.com/functoreality/my-big-brother on this machine.
Read its INSTALLATION.md and follow it. Ask which records and outputs I want.
If I use Vim or Neovim, offer session-recorder.vim and ask before installing
it or editing my editor configuration. Help me set up daily unattended reviews
with my chosen Agent. Prefer its native scheduler when suitable. Otherwise,
build the needed local runner and OS schedule using its supported execution
interface. Keep each trigger to one executing Agent that performs all review
steps itself. Verify one review in the scheduled execution environment before
enabling the schedule. Ask before starting continuous recording or installing
a recurring task.
```

The shared [INSTALLATION.md](INSTALLATION.md) guides your installing Agent.
It can also be your daily analyzer. A Codex unattended launcher and Linux,
macOS, and Windows scheduling templates are included. Other Agents can use a
native scheduled review or an automation runner prepared by the installing
Agent. They are not restricted to the bundled launcher, but an unbundled
backend needs setup and verification. Input histories and the analyzer are
independent choices.

Python 3.11+ is recommended. Older versions are unverified and compatibility
is not guaranteed. The core uses only the standard library. Optional
screenshots need Pillow. Configure `language: "zh-CN"` in your personal JSON
configuration to request Chinese reports.

For manual setup, commands, and scheduling choices, see
[Setup](docs/SETUP.md), [Scheduling](docs/SCHEDULING.md), and
[Vim/Neovim recording](docs/VIM.md). Scheduled execution is optional and is
not enabled by initialization.

## Personal files

Run `python -m my_big_brother paths` to find configuration, captures, results,
and runtime state. Your installation can be moved or updated without storing
personal history inside Git.

- `config.json` selects sources, outputs, language, and the analyzer.
- `local_profile`, when selected, names personal rules, permitted references,
  output overrides, validators, and optional post-review operations.
- Optional `storage.json` selects the shared data root. Collectors default to
  platform paths and use natural calendar dates.
- `daily/DATE/` holds disposable captures, drafts, sheets and execution logs.
- `memory/` holds published reports, directly visible user/machine knowledge,
  and minimal durable system facts. Delete inactive old dates without reading
  state files. Removed dates are not automatically recreated.
- See [Storage](docs/STORAGE.md) for the collector contract and [Requirements](docs/REQUIREMENTS.md).

Native Agent histories stay in their own locations. This MVP does not
automatically delete captures or run materials. Review and manage their disk
usage separately. Excerpts can contain private conversation text.
The optional Bash recorder is described in [BASH.md](docs/BASH.md).

Another Agent can discover results through `paths` and read only the relevant
dated reports. A useful global instruction is: "For my recorded work history,
consult My Big Brother at <installation path> and use its paths command."
Installing this repository does not automatically expose it to every Agent.

## Scope and extension

The portable core is intended for Linux, macOS, and Windows. An isolated
end-to-end run, including same-Agent post-review, has been verified on Linux
with fictional records. Complete macOS and Windows runs and their scheduled
actions still require validation on those systems.
Bash support applies to Bash environments, including WSL as a separate
environment, and does not record PowerShell.

There is no built-in weekly-report command. Optional standard knowledge
outputs share the daily review, with no extra Agent or machine-wide scan.
Existing daily files can be summarized by your Agent. Explicit personal
post-review tasks can maintain selected local knowledge or cumulative records.
They run after checked publication and have separate completion/retry state.
See [Profiles](docs/PROFILES.md) for configuration and boundaries. See
[EXTENDING.md](docs/EXTENDING.md) for the boundaries between collectors,
input adapters, analysis tasks, and independent Agent startup entries.

Run the isolated test suite from the repository:

```sh
python -m unittest discover -s tests -v
```

On Linux, `python3 tests/smoke.py` prepares an isolated fictional workday.

the isolated fixture directory. That optional step uses your installed account
and consumes quota. It does not use personal histories or install a scheduler.
